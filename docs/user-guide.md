# 通勤圈使用说明

更新日期：2026-10-07

通勤圈用于按上班通勤条件筛选住宅小区：先找公司附近的接驳站，再沿真实公交、地铁或有轨电车线路查找可达站点，最后核验小区到公司的完整路线。当前只计算「住所 → 公司」，不计算下班回程，也不提供房源、租金或可租库存。

## 快速开始

1. 首次进入时，按引导选择工作地点、通勤预算、出发时间和本机记忆；已有记录会恢复设置。可从页面右上角「重新设置」再次进入引导。
2. 在「01 设置条件」确认日期和时间，从公司附近 500 米开始搜索，选择接驳站及允许乘坐的线路，再计算通勤圈。
3. 在「02 查看线路」检查各站点、线路和方向的结果，点击路线卡片在地图上高亮；边界尚未确认时可继续补查。
4. 在「03 找小区」选择已核验可达的沿线上车站，搜索小区，勾选感兴趣的小区后点击「核验所选」。
5. 查看门到门耗时、两端步行和预算状态；需要时校正大门并重新核验，再收藏或比较候选。

通勤圈中的站点可达，只表示站点阶段的核验结果；加上小区到站的步行后可能超过预算。选房时应以完整小区路线核验为准。

## 设置工作地点和通勤条件

在地点输入框搜索后，选择正确的地点候选。先核对地图位置；若公司 POI 位于园区中心，可用「校正公司入口」改为实际通行大门。

- **通勤预算**：20～90 分钟，按 5 分钟调整。
- **日期与出发时间**：时间指从住所出发，不是到公司打卡的时间。恢复的日期已过期时，需明确选择今天、明天或指定日期后才能核验。
- **公司附近站点半径**：500 米、1 公里、1.5 公里三档，为直线搜索半径，不是步行距离。建议先用 500 米，不够再扩大。
- **接驳站与线路**：最多选择 3 个公司侧接驳站；可查看途经线路并限制允许乘坐的线路。不限定线路时允许该站全部线路，单次仍最多 8 条「站点 + 线路」组合，超出需缩小选择。

计算后设置会收起为摘要，点击「修改」可展开，原有选择仍保留。公交、地铁、有轨电车能否返回完整线路，取决于高德在所在城市的数据覆盖。

## 查看线路与理解计算结果

站点阶段先取得「公司位置 → 接驳站」的步行时间，再从总预算中扣除，得到该站的公共交通预算。然后按「接驳站 + 线路 + 运行方向」分别读取真实站序，核验能沿该方向乘车到公司侧接驳站的上游站点。

线路的两个运行方向分别计算，不代表额外计算公司到住所的回程。不同接驳站、线路和方向不会共用一个候选池；结果数也不保证等于所选站点数的两倍——终点站可能没有上游站，某些方向也可能无匹配方案、步行已耗尽预算或查询失败。

| 结果或提示 | 含义与下一步 |
| --- | --- |
| 本方向最远站已确认 | 已核验到线路端点，或所有更远候选均有超预算证据；仅针对这条直达线路方向 |
| 最远边界待确认 | 已有可达站，但不能断言是最远站；使用「补查此方向」继续 |
| 超过预算 | 匹配方案已返回，但总耗时大于当前预算 |
| 指定方案未匹配 | 高德未返回满足所选线路、方向和上下车站的方案；不等于现实中无车可乘 |
| 接口失败 | 请求未成功，不是不可达结论；按错误提示处理后重试 |
| 历史结果或需要更新 | 条件不一致或证据已过期，不能直接作为当前可达结论 |

每个方向每轮最多新增 8 次站点核验。优先用「补查未完成」或「补查此方向」继续，避免重复查询已确认部分；「更多更新 → 全部重新查询」会忽略缓存并增加调用。展开「计算详情」查看逐站记录，「计算概况与步行预算」查看汇总。

计算中可「停止计算」，已完成结果保留，之后继续时复用仍有效证据。已发出的请求无法撤销；服务端重启、切换实例或缓存过期后可能重新查询。“已处理方向数”不等于“最远边界已确认方向数”。

## 在地图上看清路线和小区

- 「通勤线路 / 候选小区」切换不同图层，各自保留本页内的视野和选中项。
- 点击路线卡片，当前路线加粗高亮，其他路线以浅色显示；重合时可用「只看当前路线」，再用「查看全部路线」恢复。
- 公共交通用实线，步行用虚线；有路线数据时同时标注上下车站和沿途站点。
- 点击小区标记会打开对应卡片；重叠标记会提供选择列表。卡片与地图同步定位，也可「查看全部小区」。
- 收藏中的「定位」只展示小区和对应公司位置，不代表重新核验或重新生成路线。

这些操作只切换已有数据，不重新发起地点检索或路线核验；地图底图本身仍可能加载数据。

## 搜索并核验沿线小区

1. 在「03 找小区」选择最多 3 个已核验可达的上车站。途中已核验站也能选，不只最远站；未核验的沿途站不会直接当成可达。
2. 选择 500 米或 1 公里的小区搜索半径，点击「搜索小区」。这是上车站周围的直线半径，与公司附近站点的三档半径不同。
3. 每站每页最多 20 个小区，可「加载更多小区」，每站最多 60 个；同一小区自动合并，保留不同上车站和线路候选。
4. 点击「查看详情」，核对地址、上车站及线路。多方案时可切换；需要时先校正小区大门。
5. 点击「补查此小区」或「更新此路线」，也可先勾选再「核验所选」，每批最多 5 个。只处理当前显示且未排除的所选项；筛选隐藏的勾选项会取消，有效核验优先复用。
6. 查看「小区步行 + 公共交通（含候车）+ 到公司步行」和总耗时。有几何数据时可「查看完整路线」，否则只定位。

完整路线以设置的小区出发时间向高德查询，严格匹配指定线路、方向及上下车站。总耗时取完整方案，包含两端步行和候车，不再重复加上站点阶段的步行预算。缺少的步行明细会标为待确认，不按零分钟计算。

可用「仅看预算内」及「步行偏好」筛选：分别限制小区到站步行、两端合计步行，查看全部、符合偏好或待确认项。筛选只使用已有核验，不额外请求路线，也不改变通勤圈算法。

不感兴趣的可「暂不考虑」，通过「显示暂不考虑」再「恢复考虑」；排除不删除收藏。「更多更新 → 更新小区名单」只刷新 POI 名单，保留仍有效的路线核验。

## 校正公司和小区实际入口

公司卡片点击「校正公司入口」，小区详情点击「校正小区入口」，收藏卡片点击「校正入口」。

1. 在地图上点击实际大门，核对「原 POI」「待保存入口」和距原位置的距离。
2. 也可输入坐标，格式为 `经度,纬度`，必须使用高德 GCJ-02 坐标，不能直接混用其他坐标系。
3. 点击「确认保存入口」生效；「取消」不保存。若需还原，先「恢复原 POI 位置」，再确认保存。
4. 入口改变后重新核验：公司入口变化会重置附近站点和通勤结果；小区入口变化后，旧坐标的核验不能作为新入口结论，相关收藏核验也会清空。

入口距原 POI 最多 3 公里，最多保存 40 个；更远应重新搜索地点。点选和保存本身不请求路线。校正不保证大门开放或实际可步行，也不自动计入楼栋内部、园区内到工位的时间。

## 收藏与三种对比

在小区卡片点击「收藏小区」；已有收藏可更新。最多 20 个，按公司位置与小区区分，独立于查询缓存保存，每个收藏保留一条选定方案的快照，不保留完整路线几何。

| 想比较什么 | 操作入口 | 数量与查询方式 |
| --- | --- | --- |
| 不同小区哪个更合适 | 「收藏与对比」中勾选收藏 | 2～3 个，只比较已保存快照，不自动查询 |
| 同一小区坐哪条线路 | 小区详情 →「对比候选通勤方案」 | 2～3 条现有候选，确认后核验，有效证据复用 |
| 同一小区几点出发更合适 | 收藏卡片 →「时段对比」 | 同一天 2～3 个不同时间，确认后按固定线路核验 |

### 收藏重新核验

在「从收藏重新核验（最多 5 个）」中选择收藏，点击「准备核验所选」，核对当前公司、日期、时间、预算和各条线路后「确认并核验」。当前公司须与收藏匹配；旧收藏若缺少可用的线路站序，应重新搜索并更新收藏，不会自动猜测替代线路。

重新核验不重搜小区，有效结果直接复用，同条件的新结果同步到当前小区列表和地图。不同公司、日期或出发时间的快照不能直接当作同条件排名，过期记录应先重核。

### 同一小区多路线对比

在「对比候选通勤方案」中勾选 2～3 条，点击「准备对比所选方案」，核对条件后「确认开始对比」。这里只比较当前搜索得到的候选，不自动扩展所有可能线路；只有一条候选时，可选择更多已核验沿线站点搜索小区。

结果独立显示预算状态、总时间和步行。标记的「所选中总时间最短」「所选中步行最少」只针对本次有效结果，不代表城市内最优；最快的方案也可能超预算。缺失步行或已过期的证据不参与相应排名。

点击「使用此方案并定位」可切换当前方案和地图；如果该小区已收藏，会更新其选定方案快照，不会自动新增收藏。

### 收藏出发时段对比

每次对比一个收藏，保持相同公司、线路、方向和上下车站。默认建议主设置的出发时间及之前两个 15 分钟间隔，可修改为同一天 2～3 个不同时间；午夜附近不会自动跨日。点击「准备对比出发时段」，核对条件后「确认开始对比」。

结果展示各时段的耗时、步行、预算状态及差异，只在本页临时保留，不覆盖主设置或收藏的常用出发时间，也不进入本地备份。更换目标、条件或刷新页面后需重新比较。它是规划预估差异，不能据此推断班次间隔或准点率。

两类查询对比都可「停止对比」，保留已完成项；失败项独立显示，不会让其他成功结果消失。页面的“提交核验项数”不是高德实际请求次数，服务端仍可能复用缓存。

## 本机记忆和备份

默认开启本机记忆；数据只在当前浏览器保存，没有账号或跨设备自动同步。无痕浏览、浏览器清理或更换访问域名可能导致读不到原记录。重要收藏和入口请先导出备份。

| 记录 | 数量上限 | 使用方式 |
| --- | --- | --- |
| 最近工作地点 | 5 个 | 恢复地点与条件 |
| 附近站点查询 | 6 组 | 同条件 24 小时内复用 |
| 通勤结果 | 4 次 | 同条件完整结果 10 分钟内复用，未完成结果继续补查 |
| 小区查询 | 3 组，每组约 1.5 MB | 名单与路线分开保存；路线核验 10 分钟有效 |
| 收藏 / 暂不考虑 / 入口校正 | 20 / 100 / 40 条 | 共享约 500 KiB 上限，超限需整理，不静默淘汰收藏 |

查询历史最长保留 7 天；收藏不会因为查询缓存淘汰而丢失，但也不会延长路线证据有效期。修改预算可按已有原始耗时重判；公司或小区坐标、线路、日期、出发时间改变后，不能把旧条件核验当成新条件结论。服务端缓存是实例内的尽力复用，不能保证每次恢复都不调用 API。

### 导出与导入

在「设置条件 → 本机记忆 → 本机数据管理」中：

1. 点击「导出本地备份」，保存 JSON；若未自动下载，可点「下载已生成的备份」。
2. 导入时选择不超过 1 MB 的 JSON，先查看收藏、排除、入口和地点数量。
3. 默认只合并记录；若也要替换当前工作地点和通勤条件，额外勾选对应选项，再「确认合并导入」。

备份包含地点、入口校正、偏好、收藏和排除，不包含密钥、查询缓存或路线几何；导出和导入不会上传备份文件。相同公司与小区的已有收藏优先保留，超出数量或容量上限则整批不导入。导入路线统一作为历史记录，须重新核验；本机记忆关闭时导入只在本页保留，不会自动开启记忆。

备份包含位置数据，请妥善保管。实际发起地点、站点或路线查询时，相关查询条件仍会发送给服务端和高德。

### 清理与关闭记忆

| 操作 | 清理范围 |
| --- | --- |
| 清理查询缓存（保留收藏） | 附近站点、通勤、小区查询；保留地点、条件、收藏、排除及入口校正 |
| 清空收藏与排除 | 收藏和暂不考虑；保留入口校正、地点与查询缓存 |
| 清除全部本机记录 | 包含地点、入口、查询缓存、收藏、排除的全部本机记录 |

清理需确认；建议先备份。清理查询缓存会中止当前计算并收起通勤和小区结果，附近站点暂留本页。全部清理后当前地点与条件仍可能留在页面，后续操作可能重新记忆。

**关闭本机记忆也会清除已保存记录，包括收藏和入口**，并非只暂停写入。关闭期间的新操作仅在本页保留。

## 常见问题

### 为什么选了多个站点却没有对应数量的路线

查看每个接驳站下各线路方向的状态和「计算详情」，确认是否无上游站、步行预算不足、方案未匹配或接口失败。地图只展示有可用路径数据的结果；重合时点击路线卡片，再「只看当前路线」。未确认的边界可定向补查，不需要每次全部重新查询。

### 为什么站点可达，小区却超预算

站点阶段用于寻找候选范围，小区阶段才包含住宅端步行并重算完整方案。小区大门位置、实际地铁出入口、出发时间和候车都会影响总耗时，二者不是同一个起终点查询。

### 地铁或公交显示失败，是不是无法通勤

不是。先区分“接口失败”和“指定方案未匹配”，查看错误提示、线路方向及上下车站。可重试目标项，或明确改选另一条候选方案；不要把失败当成超预算证据。持续失败时反馈公司地点、所选站点/线路、日期时间和错误截图，无需提供密钥。

### 怎样减少 API 调用

先选少量接驳站与线路，再核验真正感兴趣的小区；优先补查未完成项、复用近期结果。步行筛选、地图定位和收藏快照对比不重查路线。路线或时段对比只勾选需要的 2～3 项，并在确认页检查预计提交量。

### 页面、地图打不开怎么办

本地运行见 [README 的本地运行说明](../README.md#本地运行)，开发服务需要保持运行，以终端实际地址为准。页面能打开但地图报错时，检查网络及地图配置提示；自行部署者检查 Key 类型、授权域名和接口权限，不要将 `.env.local` 或密钥发到公开仓库、截图或反馈中。

## 使用边界

当前是指定直达线路的有界核验，不是完整换乘网络、连续等时圈或所有小区的穷举。高德住宅 POI 可能存在误分类；线路、运营信息和耗时以接口返回为依据，不保证实时班次、道路开放情况或实际准点。看房前仍应核实大门、步行通道、运营时间和实际通勤体验。
