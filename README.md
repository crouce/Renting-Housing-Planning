# Renting Assistance Service

面向租房通勤决策的地图工具。选择公司或学校、设置出发时间和通勤预算，先找可达的公共交通站点，再搜索沿线住宅小区并核验“小区 → 公司”的完整通勤路线。当前不提供实际房源、租金或可租库存。

## 当前状态

当前 Web 应用已具备地点与站点搜索、真实线路双方向边界核验、沿线小区搜索、门到门通勤核验、收藏与本机备份。支持实际入口校正、同小区多路线对比和收藏出发时段对比。仅计算住所到公司的上班方向；结果是高德规划预估，不是完整等时圈或实时到站预测。

## 开始使用

完整操作见 **[通勤圈使用说明](docs/user-guide.md)**（更新于 2026-10-07）。

1. 在「01 设置条件」选择工作地点、日期、住所出发时间及通勤预算。
2. 从公司附近 500 米开始找站，选择接驳站和线路，再计算通勤圈。
3. 在「02 查看线路」检查各方向结果；需要时补查未确认的边界。
4. 在「03 找小区」选择已核验可达的上车站，搜索并勾选小区做完整核验。
5. 校正实际大门后重新核验，收藏候选，并按需对比小区、路线或出发时段。

新手建议先选少量站点和小区；地图定位、筛选和收藏快照对比不会重新查询路线。备份与清理入口在「设置条件 → 本机记忆 → 本机数据管理」。

## 当前主要能力

- 地点输入提示、POI 定位和入口地图选点
- 附近公交、地铁、电车等站点查询
- 站点线路、方向和运营信息展示
- 按真实线路方向核验指定直达路线与最远可达边界
- 在地图上展示、高亮路线及沿途站点
- 在已核验可达站点附近搜索住宅小区，核验完整通勤并按步行偏好筛选
- 校正公司和小区入口，对比小区、路线与出发时段
- 本机记忆、收藏、分类清理与 JSON 备份导入导出

## 当前技术栈

- Web：React + TypeScript，Next.js 风格 App Router，由 vinext / Vite 运行与构建
- API：`apps/web/app/api` 内的服务端路由，高德 Web 服务 API 由服务端调用
- 地图：高德 JS API；本机数据使用浏览器存储，服务端使用有界实例缓存
- 工程：在 `apps/web` 使用 npm；Sites / Cloudflare 承载线上应用

早期文档中的独立 API / Worker、PostgreSQL / PostGIS、Redis 和 pnpm workspace 是目标规划，并非当前运行所需依赖。

## 本地运行

推荐使用本地初始化助手。Windows 用户双击仓库根目录的 `start-local.cmd`；macOS 或 Linux 用户运行：

```bash
node scripts/local-setup.mjs
```

助手会在浏览器中检查 Node.js 版本、填写或复用高德配置、自动安装依赖并启动应用。它会识别项目根目录及 `apps/web` 下的 `.env.local`，兼容 Windows 记事本保存的 BOM、引号和 `export KEY=...` 写法；界面只显示各项是否已识别，不会回显密钥。若配置位于 `apps/web`，启动时会把有效配置合并到项目实际读取的根目录 `.env.local`。高德密钥不会发送到线上或提交到 Git。

也可以手动启动当前 Web 应用：

```powershell
cd apps/web
npm install
npm run dev
```

开发地址默认为 `http://localhost:3000/`。

当前 Web 版本已实现高德地图加载、地点输入提示、地图定位、通勤条件设置、500 米/1 公里/1.5 公里三档公共交通站点查询、途经线路展示，以及基于真实线路站序的“候选住所 → 公司”公共交通可达性计算。计算前可选择最多 3 个公司侧接驳站点，并可限定具体公交或轨道线路。系统先通过高德步行规划取得“公司地点 → 接驳站”的时间 1，再用总预算减去时间 1 得到每个站点的公共交通预算时间 2；候选站来自接驳站途经线路的完整站序，并由公共交通路径规划逐个复核。地图同步标注上车站、途经站和下车站，乘车段使用实线、步行段使用虚线。点击结果列表可切换并高亮对应路线。当前算法是配额可控的直达线路抽样，不是完整换乘网络或连续等时圈。

首次进入会先显示初始化页面，引导用户完成工作地点、通勤预算、出发时间和本地记忆设置，再进入地图规划；已保存工作地点的用户会自动恢复设置并跳过初始化。地图主页面右上角保留“重新设置”入口，初始化尚未完成时也允许暂时跳过。

浏览器本机记忆默认开启，可由用户随时关闭和清除。容量按数量控制：最近工作地点最多 5 个、附近站点查询最多 6 组、完整通勤结果最多 4 次。站点记录 24 小时内直接复用，通勤结果 10 分钟内按地点、预算、日期时间、接驳站和限定线路精确复用；两类记录最长保留 7 天，过期后只作上次结果或接口失败兜底。地图密钥不会写入浏览器存储。

选择多个公司侧接驳站时，系统会按“接驳站 + 指定线路 + 线路方向”建立独立计算单元，不再共享候选站池。每个方向只使用该方向完整站序中位于接驳站上游的站点，并在扣除公司到接驳站的步行时间后，按剩余公共交通预算查找最远可达站。左侧按接驳站分组展示每条线路的方向和状态，地图默认同时绘制所有可达方向；当前选择的路线保持加粗高亮，其他路线以浅色显示。

每个方向每轮最多新增 8 次站点核验，单选和多选采用相同规则。边界搜索优先检查端点、近站和预算边界，并继续检查更远的站点；只有已验证到达线路端点，或所有更远候选均有超时证据时，才标记“本方向最远站已确认”。未完成时显示“已验证可达 · 最远边界待确认”，可点击“补查此方向”。接口失败、未返回匹配的直达方案、尚未核验和已验证超时分别展示，并提供沿线核验记录。线路核验要求匹配线路 ID/方向、上下车站及途经站序，排除其他线路与换乘方案；兼容高德两个接口采用不同站点 ID 的情况。

服务端按方向复用近期证据，方向和步行缓存保留 10 分钟，线路缓存保留 24 小时，并按条数和大小限制容量。它们是运行实例内的尽力缓存，实例重启或切换后可能重新核验；本机完整结果记忆仍遵循原来的 4 次上限。重试只更新目标方向，已取得明确结论的检查点不重复请求。单次最多选择 8 条“站点 + 线路”组合，超出时提示缩小选择，不再静默截掉线路。默认“补查未完成”只继续未确认的边界和失败部分；“更多更新 → 全部重新查询”才忽略缓存重新请求。

在 `apps/web` 中运行 `npm test` 可验证单选/多选一致性、严格线路匹配、异常分类、边界继续核验和定向合并；测试使用固定上游数据，不消耗高德额度。

## 沿线小区搜索

页面分为「01 设置条件 → 02 查看线路 → 03 找小区」。计算完成或恢复结果后，设置自动收起为摘要，可随时点击“修改”展开；原有地点、站点和线路选择仍然保留。每个方向只显示一张路线卡片，逐站核验和耗时明细位于“计算详情”，整体查询统计位于“计算概况与步行预算”。

计算通勤圈后，在「03 · 找小区」选择已核验可达的上车站（每批最多 3 个），按 500 米或 1 公里直线半径搜索住宅小区。不仅最远站，已核验可达的途中站也可选；尚未核验的途中站不会被直接当成可达。小区卡片默认显示名称、门到门时间、预算状态和上车站，点击“查看详情”展开地址、分段耗时和核验操作；只有多条候选路线时才显示线路选择器。

- 每站每页 20 个候选，最多加载 3 页；同一 POI 自动合并，保留不同上车站和线路选择。超过上限会提示，结果不代表城市内全部小区。
- 点击「补查此小区」，或先勾选再使用「核验所选」（每批最多 5 个），以用户设置的小区出发时间请求完整的“小区 → 公司”公交规划，并严格核对指定线路、方向和上下车站；已有有效证据直接复用。
- 总耗时使用该完整方案的 `cost.duration`，已包含两端步行和候车，不再叠加站点基线耗时。显示“小区步行 + 公共交通（含候车）+ 到公司步行”；分段缺失时明确提示，不按直线距离或零秒补齐。
- 核验结果区分预算内、超过预算、接口失败和方案未匹配。可仅筛选预算内小区；点击「查看完整路线」绘制两端步行虚线、乘车实线及沿途站点。
- 本机最多记住 3 组小区查询，每组最多约 1.5 MB；完整核验 10 分钟内复用，过期后须重新核验。服务端住宅 POI 缓存最多 64 页 / 1 MiB / 24 小时，完整路线缓存最多 96 条 / 4 MiB / 10 分钟。小区名单与路线核验分开保存：修改预算直接按原始秒数重判；更换沿线站点批次或半径后，对相同小区、上/下车站、线路、公司位置和出发时间继续复用有效核验。地点坐标、线路或时间改变则不复用旧路线。关闭记忆和清空记录同时适用于小区数据。

小区数据来自[高德 POI 周边搜索](https://lbs.amap.com/api/webservice/guide/api/newpoisearch)，路线来自[路径规划 2.0](https://lbs.amap.com/api/webservice/guide/api/newroute)。这里只是住宅小区 POI，不提供租金、户型、可租库存或房源真实性保证。默认以 POI 坐标为端点，可校正为实际大门；仍不包括楼栋内部到大门、园区入口到工位等未纳入规划的路程。完整方案可能选取不同地铁出入口，因此与站点阶段的分段时间可能不同。

## 更新与缓存复用

- 结果区统一使用“补查未完成”，单方向使用“补查此方向”；补查期间保留现有列表和路线。完整刷新收进“更多更新”，明确提示会增加接口调用。
- 小区“更多更新 → 更新小区名单”只更新住宅 POI，不清除有效通勤证据；失败站点保留旧名单，后续补查重试原来失败的页。小区位置变更后，旧路线证据不再匹配。
- 服务端按“接驳站 + 线路方向 + 真实站序 + 日期时间”保存预算无关的路线耗时和几何；每条证据保留原核验时间。增加/缩短预算会重新分类，只有缺失或已过期的边界证据才调用高德，不把超时、失败、未匹配混为一谈。
- 前端显示“近期结果 / 历史结果 / 需要更新”。路线证据有效期统一为 10 分钟，POI 名单仍为 24 小时；读取、改预算或补查其他方向不会延长已有路线的有效期。历史结果最长保存 7 天，过期小区通勤不计入“预算内”。
- 本机数量上限仍为 5 个地点、6 组附近站点、4 次通勤、3 组小区；服务端方向证据仍限 48 组 / 4 MiB。没有引入持续轮询或无限增长缓存。

## 日期、地图视图与计算进度（2026-10-07）

- 恢复本机记忆时，已过期的出发日期会提示确认今天、明天或指定日期，不自动修改查询条件。工作地点、常用出发时间和站点选择保留；过期日期无法发起路线核验，服务端也会校验北京时间的有效日期。
- 地图提供“通勤线路 / 候选小区”两个视图，各自保留本次页面内的选中项、中心点与缩放；“查看全部路线 / 只看当前路线”只切换已有图层，不调用搜索或规划接口。改变查询条件时重置对应地图记忆。
- 通勤计算逐方向返回已完成结果，展示当前阶段、已处理/总方向数、本轮真实高德请求次数（含重试）及缓存证据复用数。“已处理”不等于边界已确认，原有边界证据规则不变。
- “停止计算”会中止连接并停止后续查询，已发出的请求无法撤销。已完成结果保留在页面，并按原有 4 次上限保存部分结果；服务端每完成一个站点核验就保存证据。继续时复用仍有效证据，补查剩余部分。实例切换、重启或缓存过期后可能重新核验，不承诺永久断点任务；停止前尚无完整方向返回时，仅当前页面保留继续入口。

## 小区挑选、步行偏好与收藏对比（2026-10-07）

- **按需核验**：先勾选最多 5 个小区，再点击「核验所选」。只核验当前显示、未排除且缺少有效证据的所选项；筛选隐藏的项会取消勾选，避免意外消耗接口额度。支持「暂不考虑 / 恢复考虑」，按公司位置区分，最多记住 100 条；排除不会删除收藏。
- **步行偏好**：可限制「小区到站最多步行」和「两端合计最多步行」，按完整门到门方案的原始秒数筛选。可查看全部、仅符合偏好或仅待确认；缺失、失败或超过 10 分钟的证据标为待确认，不按零秒处理。筛选同步地图小区标记，不额外请求 API；偏好属于本次小区查询，不改变通勤圈算法。
- **收藏与对比**：最多收藏 20 个小区，以「公司位置 + 小区」区分，独立于查询缓存保存；缓存淘汰不会清除收藏。每条保留一份选定线路和最近保存/核验快照，不保存路线几何；总大小约限 500 KiB，达到上限提示整理，不静默淘汰收藏。勾选 2～3 个可比较总通勤、两端步行、公交时间、线路方向和核验时间。
- **时效与隐私**：收藏不延长路线的 10 分钟有效期；公司、出发日期/时间改变或证据过期后，明确显示历史记录，不能当成当前可达结论。收藏与对比不自动查询；已收藏小区再次核验时更新快照。数据只在当前浏览器保存，不跨设备同步。关闭本机记忆或「清除全部本机记录」会一并清除收藏与排除记录；关闭期间新操作只在当前页面保留。

## 地图联动、收藏复核与本地备份（2026-10-07）

- **地图与列表双向联动**：点击小区标记打开并定位对应卡片，点击卡片定位地图。标记区分待核验、预算内、超预算与收藏状态；当前缩放下重叠的标记提供小区选择列表。仅切换已有数据，不调用地图搜索或规划 API。
- **收藏直接复核**：收藏区支持定位，以及最多 5 个收藏按当前公司、日期、出发时间和预算重新核验；提交前明确展示各自的线路方向与上下车站。保持收藏中的精确线路，不重新搜索小区或猜测替代路线；有效核验直接复用。取消或更改条件会停止后续请求，已经发出的请求无法撤回。同条件的最新结果同步到小区列表与地图，收藏仍不保存路线几何。旧收藏若缺少线路站序且当前结果无法唯一补足，会提示重新搜索并更新收藏。
- **分开清理**：在「设置条件 → 本机记忆 → 本机数据管理」中可选择仅清理查询缓存（保留地点、偏好、收藏、排除和入口校正）、清空收藏与排除（保留入口校正），或清除全部本机记录。清理前显示影响范围并确认；清理缓存中止当前计算并收起通勤/小区结果，附近站点暂留本页。
- **本地 JSON 备份**：导出地点、入口校正、偏好、收藏与排除，排除密钥、查询缓存和路线几何，不上传服务器。导入最多 1 MB，先校验、预览再确认；相同公司与小区的已有收藏优先保留，超出数量或容量上限拒绝整次合并。新导入证据统一作为历史记录，须重新核验；是否恢复工作地点和条件由用户显式选择，导入不会自动开启本机记忆。备份包含位置数据，请妥善保管。

## 实际入口校正（2026-10-07）

工作地点、小区详情及收藏均提供「校正入口」：点击地图选择大门、确认后保存，保留原 POI 坐标并可恢复。入口距原位置限 3 公里，最多保存 40 个，和收藏共享约 500 KiB 上限；关闭记忆仅本页保留。保存不调用路线接口；公司入口变化重置站点/通勤结果，小区入口变化按新坐标隔离证据，受影响收藏核验清空。重新核验以校正坐标为端点，不用原 POI ID 覆盖新入口。查询缓存清理和单独清空收藏保留入口，全部清理会移除入口；JSON 备份包含原坐标与校正坐标。

地图拾取使用[高德 JS API 点击事件](https://lbs.amap.com/demo/javascript-api-v2/example/map/click-to-get-lnglat/)。入口由用户指定，不代表已验证为开放或可通行的大门。

## 同一小区多方案对比（2026-10-07）

小区详情中的「对比候选通勤方案」可勾选 2～3 条现有上车站/线路方案，确认公司、时间和所选线路后核验。只比较用户所选方案，不搜索未知组合；同条件有效证据复用，其他逐项请求，可停止且保留已完成结果。按原始秒数突出所选有效结果中的最短总时间、最少两端步行；缺失步行或过期/失败结果不参加相应排名。点击「使用此方案并定位」切换当前路线，并在已收藏时更新其快照。

## 收藏出发时段对比（2026-10-07）

收藏卡片点击「时段对比」，每次对一个收藏比较同一天 2～3 个不同出发时间，保持原线路、方向与上下车站。默认建议当前时间及此前两个 15 分钟间隔，可修改；午夜附近建议保持同一天。明确确认后才查询，重复对比复用 10 分钟内的同条件证据；支持停止、失败项独立显示。结果只保留本页、最多三个时段快照，不覆盖收藏的常用出发时间，不增加持久化缓存上限。展示各时段预算状态、步行与耗时差异，仅代表高德规划预估，不能推断班次间隔或准点率。
