# Renting Assistance Service

面向租房通勤决策的地图服务。用户选择公司、学校等目的地并设置出发时间和通勤预算后，系统计算公共交通可达站点、边界站点和可达区域，后续再结合住宅小区与房源信息提供筛选和排序。

## 当前状态

项目已完成 M1 地图基础能力，并实现 M2 的第一版可达性闭环。当前 Web 应用使用高德 JS API 和 Web 服务 API，可搜索工作地点、查询附近公共交通，并按日期、时间和预算扫描“候选住所 → 公司”的可达站点及最远边界。

## 计划中的主要能力

- 地点搜索、地理编码和地图选点
- 附近公交、地铁、电车等站点查询
- 站点线路、方向和运营信息展示
- 基于出发时间与通勤预算计算公共交通可达范围
- 展示最远站点、各方向边界站点和最佳路线
- 在可达站点附近搜索住宅小区并进行通勤评分

## 技术方向

- Web：Next.js + React + TypeScript
- API：Node.js + TypeScript（框架在初始化阶段确定）
- Worker：异步执行批量路线和可达性计算
- 数据：PostgreSQL/PostGIS + Redis
- 工程：pnpm workspace + Docker

技术栈可在接入地图 API 前调整；领域模型和地图适配接口不依赖具体供应商。

## 本地运行

推荐使用本地初始化助手。Windows 用户双击仓库根目录的 `start-local.cmd`；macOS 或 Linux 用户运行：

```bash
node scripts/local-setup.mjs
```

助手会在浏览器中检查 Node.js 版本、填写或复用高德配置、自动安装依赖并启动应用。它会识别项目根目录及 `apps/web` 下的 `.env.local`，兼容 Windows 记事本保存的 BOM、引号和 `export KEY=...` 写法；界面只显示各项是否已识别，不会回显密钥。若配置位于 `apps/web`，启动时会把有效配置合并到项目实际读取的根目录 `.env.local`。高德密钥不会发送到线上或提交到 Git。

也可以手动启动当前 Web 应用：

```powershell
cd apps/web
npm install
npm run dev
```

开发地址默认为 `http://localhost:3000/`。

当前 Web 版本已实现高德地图加载、地点输入提示、地图定位、通勤条件设置、500 米/1 公里/1.5 公里三档公共交通站点查询、途经线路展示，以及基于真实线路站序的“候选住所 → 公司”公共交通可达性计算。计算前可选择最多 3 个公司侧接驳站点，并可限定具体公交或轨道线路。系统先通过高德步行规划取得“公司地点 → 接驳站”的时间 1，再用总预算减去时间 1 得到每个站点的公共交通预算时间 2；候选站来自接驳站途经线路的完整站序，并由公共交通路径规划逐个复核。当前选中的候选路线按每条乘车线路分别着色，地图同步标注上车站、途经站、换乘站和下车站，换乘步行段使用虚线。点击结果列表可切换并高亮对应路线。当前算法是配额可控的直达线路抽样，不是完整换乘网络或连续等时圈。

首次进入会先显示初始化页面，引导用户完成工作地点、通勤预算、出发时间和本地记忆设置，再进入地图规划；已保存工作地点的用户会自动恢复设置并跳过初始化。地图主页面右上角保留“重新设置”入口，初始化尚未完成时也允许暂时跳过。

浏览器本机记忆默认开启，可由用户随时关闭和清除。容量按数量控制：最近工作地点最多 5 个、附近站点查询最多 6 组、完整通勤结果最多 4 次。站点记录 24 小时内直接复用，通勤结果 2 小时内按地点、预算、日期时间、接驳站和限定线路精确复用；两类记录最长保留 7 天，过期后只作上次结果或接口失败兜底。地图密钥不会写入浏览器存储。

选择多个公司侧接驳站时，系统会按“接驳站 + 指定线路 + 线路方向”建立独立计算单元，不再共享候选站池。每个方向只使用该方向完整站序中位于接驳站上游的站点，并在扣除公司到接驳站的步行时间后，按剩余公共交通预算查找最远可达站。左侧按接驳站分组展示每条线路的方向和状态，地图默认同时绘制所有可达方向；当前选择的路线保持加粗高亮，其他路线以浅色显示。

每个方向每轮最多新增 8 次站点核验，单选和多选采用相同规则。边界搜索优先检查端点、近站和预算边界，并继续检查更远的站点；只有已验证到达线路端点，或所有更远候选均有超时证据时，才标记“本方向最远站已确认”。未完成时显示“已验证可达 · 最远边界待确认”，可点击“继续核验此方向”。接口失败、未返回匹配的直达方案、尚未核验和已验证超时分别展示，并提供沿线核验记录。线路核验要求匹配线路 ID/方向、上下车站及途经站序，排除其他线路与换乘方案；兼容高德两个接口采用不同站点 ID 的情况。

服务端按方向复用近期证据，方向和步行缓存保留 10 分钟，线路缓存保留 24 小时，并按条数和大小限制容量。它们是运行实例内的尽力缓存，实例重启或切换后可能重新核验；本机完整结果记忆仍遵循原来的 4 次上限。重试只更新目标方向，已取得明确结论的检查点不重复请求。单次最多选择 8 条“站点 + 线路”组合，超出时提示缩小选择，不再静默截掉线路。点击“更新”会主动刷新服务端证据。

在 `apps/web` 中运行 `npm test` 可验证单选/多选一致性、严格线路匹配、异常分类、边界继续核验和定向合并；测试使用固定上游数据，不消耗高德额度。

## 沿线小区搜索

页面分为「01 设置条件 → 02 查看线路 → 03 找小区」。计算完成或恢复结果后，设置自动收起为摘要，可随时点击“修改”展开；原有地点、站点和线路选择仍然保留。每个方向只显示一张路线卡片，逐站核验和耗时明细位于“计算详情”，整体查询统计位于“计算概况与步行预算”。

计算通勤圈后，在「03 · 找小区」选择已核验可达的上车站（每批最多 3 个），按 500 米或 1 公里直线半径搜索住宅小区。不仅最远站，已核验可达的途中站也可选；尚未核验的途中站不会被直接当成可达。小区卡片默认显示名称、门到门时间、预算状态和上车站，点击“查看详情”展开地址、分段耗时和核验操作；只有多条候选路线时才显示线路选择器。

- 每站每页 20 个候选，最多加载 3 页；同一 POI 自动合并，保留不同上车站和线路选择。超过上限会提示，结果不代表城市内全部小区。
- 点击「核验通勤」或每批最多 5 个的批量核验，以用户设置的小区出发时间，重新请求完整的“小区 → 公司”公交规划，并严格核对指定线路、方向和上下车站。
- 总耗时使用该完整方案的 `cost.duration`，已包含两端步行和候车，不再叠加站点基线耗时。显示“小区步行 + 公共交通（含候车）+ 到公司步行”；分段缺失时明确提示，不按直线距离或零秒补齐。
- 核验结果区分预算内、超过预算、接口失败和方案未匹配。可仅筛选预算内小区；点击「查看完整路线」绘制两端步行虚线、乘车实线及沿途站点。
- 本机最多记住 3 组小区查询，每组最多约 1.5 MB；完整核验 10 分钟内复用，过期后须重新核验。服务端住宅 POI 缓存最多 64 页 / 1 MiB / 24 小时，完整路线缓存最多 96 条 / 4 MiB / 10 分钟。更换地点、时间、预算、站点或半径会隔离查询，关闭记忆和清空记录同时适用于小区数据。

小区数据来自[高德 POI 周边搜索](https://lbs.amap.com/api/webservice/guide/api/newpoisearch)，路线来自[路径规划 2.0](https://lbs.amap.com/api/webservice/guide/api/newroute)。这里只是住宅小区 POI，不提供租金、户型、可租库存或房源真实性保证。路线以 POI 位置为起点，不等于任意楼栋到工位的实际时间；完整方案可能选取不同地铁出入口，因此与站点阶段的分段时间可能不同。
